## 14. VERSION更新・commit・main／gh-pages配信

**すべてのゲートを満たすまで実行しない。**

1. `pwa/sw.js` の `VERSION` を1つだけ上げる（現在 `forge-v32`）
2. `npm run build:all`
3. `npm run verify`
4. `git diff` 確認 → commit
5. `git push origin main`
6. `git push origin $(git commit-tree main:pwa-dist -p origin/gh-pages -m "deploy: forge-vN"):gh-pages`
7. 公開URLで新 VERSION を確認

⚠️ **main だけ push しても配信物は変わらない。push は2本。**

状態: ⬜

## 16. 3〜6週間後の個人補正評価

実運用データが溜まってから、LT / CV / 回復日数 / 暑熱補正 / progression 速度などを評価する。

**評価の前提**（先に決めておく。データを見てから基準を決めると後付けになる）:

- 遡り入力ぶんは評価に使わない（RPE・心拍・体調が欠損しているため）
- カテゴリ別に最小サンプル数を満たすまで判断しない
- 暑熱・睡眠不足で説明できる未達を能力低下と断定しない
- 1回の結果で閾値を変更しない
- 速く走れたこと・RPE が高いことを成功として扱わない
